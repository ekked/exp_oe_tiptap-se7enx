# exp_oe_tiptap 0.1.7

The AI commands can run through expai, the form token is always required, the round trip runs on a
site's own content in a sandbox copy, a typed address becomes a link, and the edit page carries no inline script: the
editor runs under a Content Security Policy without `'unsafe-inline'` in `script-src`.

## Added

- Added: AI through expai: `[AISettings] Provider=expai` sends the commands through expai's model registry, master
  switch, data policy for the edited field's object, limits and usage log (action `tiptap:<command>`). The editor
  sends the edited field's object, version, attribute and language. The provider requires expai's write policy and a
  model the user may use (`ExpaiModel` or expai's model for the user).
- Added: A typed URL is linked automatically on space or Enter (`http(s)://` and `www.`); trailing punctuation,
  quotes and unbalanced closing parentheses stay outside the link, inline atoms end the URL, no links in literal
  blocks.
- Added: Round trip on a site's own content: `run.sh <siteaccess> <sandbox> <work-dir>` with an SQLite copy or a
  MySQL copy named `*_sandbox` / `*_rt`, never the live database; `run.sh` finds siteaccesses of extensions, and the
  SQLite sandbox is compared with the live file by device and inode. Fixtures for the `math_latex`/`math_mathml`
  custom tags and for lists and headings directly under a section.
- Added: `bin/php/export_roundtrip_fixtures.php` exports a site's rich text fields as round trip fixtures;
  `run.sh --fixtures=<dir>` or `EXPOETIPTAP_FIXTURES_DIR` reads them.
- Added: How to verify that `npm ci` and `npm run build` reproduce the committed bundle.
- Added: `tests/js/ui/start.test.mjs` (the template carries no inline script, its options block is JSON once the
  template values are in, every editor starts once, broken options, a bundle that comes later, an editor added after
  `DOMContentLoaded`, the start file included more than once); the PHP tests read the JSON form of the options.
- Added: Tests of the refusals of the MySQL sandbox, of the request check on a kernel without `editAccess()` and of
  a field of another language, all without a database.

## Updated

- Updated: The form token is always required: without an active ezformtoken the extension uses a session token of
  its own (rendered into the editor options, compared with `hash_equals`), for the AI call and the switch view. The
  session token is never overwritten.
- Updated: AI endpoints must use https; plain http is allowed only to loopback addresses (127.0.0.0/8, ::1,
  localhost) for local models, and no proxy is used for them. A cut answer from expai is refused, and refused
  requests are logged without secrets.
- Updated: The edited field of an AI request is checked as the edit form does: the version must be a draft of the
  user, the user must be allowed to edit the object in that language (`eZContentObject::editAccess()`, or
  `eZContentObject::canEdit()` in that language on a kernel without `editAccess()`), the attribute must belong to the
  object and, when a language is named, be the field of that language; an invalid language is refused.
- Updated: The edit template writes the editor's options as JSON after the textarea
  (`<script type="application/json" data-exp-oe-options-for="<textarea id>">`) instead of an inline call of
  `expOETiptapStart()`; every value from the installation goes through `json_encode`, the form token included, and
  the block is printed with `<` and `>` as `<` and `>` (`json_encode` leaves `<!--` as it is, and
  `<!--<script>` in a value would make the browser read past the block and skip the scripts after it). The comments
  of the options moved into the template comment above the block.
- Updated: `javascript/exp_oe_tiptap/exp_oe_tiptap_start.js`, loaded with `defer`, parses each block and calls
  `window.ExpOETiptap.init( textarea, options )`: at once when the bundle is there or the page is no longer
  loading, else when the page is parsed; without the bundle after parsing, on `DOMContentLoaded` or `load`, whichever
  comes first, so an editor added between the two still starts. Included more than once on a page, the file defines
  nothing twice and starts only the editors that have not started. Broken options leave the textarea as plain text,
  with an error in the console. `expOETiptapStart( id, options )` stays global; `expOETiptapStartAll()` starts editors
  added later.
- Updated: A typed `www.` address is linked with `https://`, not `http://`; the text stays as typed. The committed
  bundle is rebuilt.
- Updated: The MySQL sandbox of the round trip is also refused when its name is the `[DatabaseSettings] Database` of
  any siteaccess or of `settings/override/`, and it must contain the marker table `exp_oe_tiptap_sandbox`, which the
  copy procedure creates in the copy (doc/content-mapping.md).
- Updated: `bin/php/export_roundtrip_fixtures.php` runs in one database transaction that is always rolled back, and
  refuses to run without `[DatabaseSettings] Transactions=enabled`: `inputXML()` can create image aliases, so the
  export is not read only, as it claimed. Alias files written to disk stay, as do rows in tables without transactions
  and the metadata of a cluster file handler with a database of its own.
- Updated: Tests after 0.1.5: the version test checks for the changelog of the version instead of a fixed number, and
  the fake provider writes its log into the system temp directory.
- Tiptap's core still adds one `<style>` element: `style-src` needs `'unsafe-inline'` where the editor is used.

## Fixed

- Fixed: A block embed at the start of a table cell is stored without the placeholder text "ezembed" (tables wrapped
  in a paragraph emptied the placeholder only outside tables).

## Upgrading

- `[AISettings] Provider=expai` removes the reasoning of reasoning models from the answer with expai 0.0.1.5 or
  later (`expAiText::stripReasoning()`); with an older expai the answer is used as the model gave it.
