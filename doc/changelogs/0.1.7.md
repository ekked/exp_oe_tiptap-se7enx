# exp_oe_tiptap 0.1.7

Not released yet. The edit page carries no inline script: the editor runs under a Content Security Policy without
`'unsafe-inline'` in `script-src`.

## Updated

- Updated: The edit template writes the editor's options as JSON after the textarea
  (`<script type="application/json" data-exp-oe-options-for="<textarea id>">`) instead of an inline call of
  `expOETiptapStart()`; every value from the installation goes through `json_encode`, and the block is printed with
  `<` and `>` as `\u003c` and `\u003e` (`json_encode` leaves `<!--` as it is, and `<!--<script>` in a value would
  make the browser read past the block and skip the scripts after it). The comments of the options
  moved into the template comment above the block.
- Updated: `javascript/exp_oe_tiptap/exp_oe_tiptap_start.js`, loaded once per page with `defer`, parses each block and
  calls `window.ExpOETiptap.init( textarea, options )`, at once when the bundle is there, else when the page is
  parsed. Broken options leave the textarea as plain text, with an error in the console. `expOETiptapStart( id,
  options )` stays global; `expOETiptapStartAll()` starts editors added later.
- Tiptap's core still adds one `<style>` element: `style-src` needs `'unsafe-inline'` where the editor is used.

## Added

- Added: `tests/js/ui/start.test.mjs` (the template carries no inline script, its options block is JSON once the
  template values are in, every editor starts once, broken options, a bundle that comes later); the PHP tests read
  the JSON form of the options.
