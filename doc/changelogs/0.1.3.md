# exp_oe_tiptap 0.1.3

A second look for the editor, skin a4: Tiptap in admin4's look, with Tiptap's own icons, a bubble menu over selected
text and an insert menu beside an empty line. And a fix for the line after block embeds, which Tiptap lost on
saving. From pull request #1, refined on merge.

## Added

- Added: Skin a4, chosen per siteaccess with `exp_oe_tiptap.ini [EditorSettings] Skin=a4`
  (`settings/siteaccess/<siteaccess>/exp_oe_tiptap.ini.append.php`). A flat toolbar with Tiptap's own icons
  (Lucide where Tiptap has none), bundled in the skin's stylesheet; their sources and licenses (MIT, ISC, Feather's
  MIT) are in `src/icons/`. Colors, radius, stacking layers, control height and type sizes come from admin4's
  `--a4-*` tokens, light and dark. The default look (ezoe's Skin, o2k7) is unchanged.
- Added: The bubble menu (a toolbar: bold, italic, underline, link, unlink) over selected text, and the "+" beside an
  empty line with the insert menu (image, object, table, custom tag, literal text). Both work from the keyboard:
  the bubble with the arrow keys (roving tab stop), the "+" as a menu button (`aria-haspopup`, `aria-expanded`):
  Arrow Down or Up opens the menu, the arrows, Home and End move in it, Escape closes it and returns the focus.
- Added: In skin a4 every dialog (link, anchor, image, object and file with search, browse, bookmarks and upload,
  custom tag, table, table cell, literal, special characters, help) is an admin4 card: a title without a bar and a
  short description, a close button with Tiptap's close icon, the label above each field and its hint below, a
  required mark, the secondary button left of the primary one, at most 32rem wide and a sheet of the whole width
  on a phone; colors, radius, control height and type from admin4's tokens, light and dark, and forced colors.
  o2k7 keeps the look of ezoe's popups.
- Added: The cell type (data or header cell) in the table cell dialog, as in ezoe's cell dialog.
- Added: A literal dialog for the class and the custom attributes of literal text, when content.ini gives literal
  classes or custom attributes; otherwise the literal button switches the block as before.
- Added: `ezoe.ini [EditorSettings] TagPathOpenDialog`: a click on a tag of the status bar path also opens its
  dialog (link, anchor, table, cell, custom tag, embed, literal).
- Added: Tests for the skin (icons, licenses, menus by keyboard), its tokens, its dialogs (markup, ARIA, focus),
  the settings defaults and the links without a version query.

## Updated

- Updated: A `<br>` between blocks, the `<line>` after block embeds that ezoe writes when a paragraph goes on
  (`<paragraph><line><embed/>...</line><table/>...</paragraph>`), is kept as a block-level node (`expBlockBreak`)
  where a block stands, so it survives Tiptap; a `<br>` inside a paragraph stays a hard break. Fixture s064.
- Updated: The titles of the format, alignment, list and table buttons are translated, and so are the dialog
  titles chosen by state (Insert link / Edit link, Insert table / Table properties) and the names, descriptions
  and choices of custom attributes; a custom attribute's description is a hint below its field.
- Updated: In both skins a dialog is labelled by its heading and described by its description, the focus goes to
  the first field, Tab stays inside (also past closed details and hidden parts), Escape closes it and the focus
  returns to the text. The content picker's search field and radio buttons have names; the special characters
  are a group.
- Updated: The extension leaves `Skin` undefined: its own settings are read after a siteaccess's, so a value there
  hid every siteaccess's choice.
- Updated: American English in the editor's AI command ("Summarize"; the setting value `summarise` is kept).

## Removed

- Removed: The version query on the editor's script and stylesheet links. A browser that still shows the old
  bundle needs a hard reload.
